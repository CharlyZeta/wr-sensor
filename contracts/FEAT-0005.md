# CONTRACT: Baja lógica de sensor — DELETE /api/sensores/{id}
# ID: FEAT-0005
# Status: RESOLVED (Loop completado 2026-09-09 — 22/22 ítems ✅)
# Mode: LOOP (completado 2026-09-09 — todos los ítems ✅)
# Gate-Mode: EXPRESS

## Intent
Exponer la **baja lógica** de un sensor en `sensor-registry`: el sensor pasa a
`estado = INACTIVO` y **nunca** se borra físicamente la fila (precondición: lecturas
futuras con FK en `ingestion-service`; decisión Ambiguity Log FEAT-0001). Escritura
**ADMIN-only** (como POST FEAT-0001 / PUT FEAT-0004). La reactivación queda a cargo
del PUT de FEAT-0004 (`estado=ACTIVO`); este Contract solo define la baja. Fuente
spec: §7, §4 Sensor, Ambiguity Log FEAT-0001.

## Use Case
**Actor:** Usuario autenticado con rol `ADMIN`
**Goal:** Dar de baja un sensor (INACTIVO) sin destruir su registro

### Main Flow
1. El actor envía `DELETE /api/sensores/{id}` con header `Authorization` (JWT rol
   `ADMIN`).
2. El sistema valida: token/rol ADMIN (`RolGuard.requireAdmin`), `{id}` UUID
   (400 si malformado), existencia del sensor (404 si no).
3. Si el sensor está `ACTIVO`/`MANTENIMIENTO`, el sistema persiste
   `estado=INACTIVO` (UPDATE, nunca DELETE de fila) y responde `204 No Content`.
   Si ya está `INACTIVO`, responde `204` igual (idempotente, sin cambio).

### Alternative Flows
- AF-01: Sin `Authorization` (o token inválido) → `401 UNAUTHENTICATED`.
- AF-02: Rol del token fuera de `{ADMIN}` (VIEWER/OTHER) → `403 INSUFFICIENT_ROLE`.
- AF-03: `{id}` malformado → `400 SENSOR_INVALID_ID`.
- AF-04: `{id}` UUID válido inexistente → `404 SENSOR_NOT_FOUND`.
- AF-05: Sensor ya `INACTIVO` → `204` sin cambios (idempotente, re-baja no-op).

## Business Rules
- BR-001: `{id}` debe ser UUID válido; malformado → `400 SENSOR_INVALID_ID`
  (precedente FEAT-0003/0004).
- BR-002: Sensor inexistente (id UUID válido) → `404 SENSOR_NOT_FOUND` (nunca
  DELETE implícito ni 204).
- BR-003: La baja es **ADMIN-only** (`RolGuard.requireAdmin`): VIEWER/OTHER →
  `403 INSUFFICIENT_ROLE`; sin token/token inválido → `401 UNAUTHENTICATED`.
- BR-004: **Baja lógica obligatoria**: el adapter ejecuta `UPDATE sensor SET
  estado='INACTIVO'`; está prohibido el `DELETE` físico de la fila (habrá lecturas
  con FK). La fila y su histórico persisten.
- BR-005: **Idempotente**: borrar un sensor ya `INACTIVO` responde el mismo
  resultado exitoso (204) sin ejecutar cambios (re-baja no-op).
- BR-006: Tras la baja, el sensor **permanece visible** en listado y detalle
  (decisiones FEAT-0002 BR/AC y FEAT-0003 AC-007 ya resueltas: no se filtra por
  estado). La "baja" no oculta en v1.
- BR-007: La reactivación se hace con `PUT /api/sensores/{id}` (FEAT-0004,
  `estado=ACTIVO|MANTENIMIENTO`); este endpoint no reactiva ni revierte.
- BR-008: Sin evento de dominio en v1 (sin consumidores; FEAT-0011 definirá
  mensajería). No hay chequeo de lecturas FK en registry (la tabla de lecturas no
  existe acá; el diseño de baja lógica ya lo cubre para cuando FEAT-0011 la cree).

## Acceptance Criteria
- AC-001: GIVEN un sensor ACTIVO con id X y un request `DELETE /api/sensores/{X}`
  con JWT rol `ADMIN`
  WHEN el sistema procesa el request
  THEN responde `204 NO CONTENT` y un `GET /api/sensores/{X}` posterior responde
  `200` con `estado=INACTIVO` (la fila no se borró — BR-004).
- AC-002: GIVEN el mismo sensor y un request con JWT rol `VIEWER`
  WHEN el sistema procesa el request
  THEN responde `403 FORBIDDEN` con code `INSUFFICIENT_ROLE`.
- AC-003: GIVEN un request `DELETE /api/sensores/{X}` sin header `Authorization`
  WHEN el sistema procesa el request
  THEN responde `401 UNAUTHORIZED` con code `UNAUTHENTICATED`.
- AC-004: GIVEN un id UUID válido inexistente y JWT rol `ADMIN`
  WHEN el sistema procesa el request
  THEN responde `404 NOT FOUND` con code `SENSOR_NOT_FOUND`.
- AC-005: GIVEN `DELETE /api/sensores/no-es-un-uuid` con JWT rol `ADMIN`
  WHEN el sistema procesa el request
  THEN responde `400 BAD REQUEST` con code `SENSOR_INVALID_ID`.
- AC-006: GIVEN un sensor ya `INACTIVO` y `DELETE /api/sensores/{X}` con JWT rol
  `ADMIN`
  WHEN el sistema procesa el request
  THEN responde `204 NO CONTENT` (idempotente) y el sensor sigue `INACTIVO`.
- AC-007: GIVEN un sensor dado de baja (INACTIVO) y un request
  `GET /api/sensores` con JWT rol `ADMIN`
  WHEN el sistema procesa el request
  THEN el listado **incluye** al sensor con `estado=INACTIVO` (visibilidad
  preservada, BR-006 — consistente con FEAT-0002/0003).
- AC-008: GIVEN un sensor INACTIVO y un request `PUT /api/sensores/{X}` (FEAT-0004)
  con body `estado=ACTIVO` y JWT rol `ADMIN`
  WHEN el sistema procesa el request
  THEN responde `200` con `estado=ACTIVO` (reactivación vía PUT, BR-007).

## Entities Affected
- Sensor (owner=sensor-registry): **update** exclusivo de `estado` → `INACTIVO`.
  Sin columna nueva, sin DELETE, sin borrado de histórico. Reutiliza
  `UpdateSensorPort` (UPDATE de FEAT-0004), `FindSensorByIdPort` y
  `RolGuard.requireAdmin`.

> Notas de implementación (no spec, no generan AC): caso de uso
> `DeactivateSensorUseCase/Service` (find → 404 si falta; si no está INACTIVO,
> construye el sensor con `estado=INACTIVO` y persiste vía `UpdateSensorPort`;
> si ya está INACTIVO → no-op) y endpoint `DELETE /api/sensores/{id}` en
> `SensorController` con `@ResponseStatus(NO_CONTENT)` sobre `Mono<Void>`.

## Ambiguity Log
- [x] Método HTTP: RESUELTO (humano 2026-09-09) = **`DELETE /api/sensores/{id}`** con semántica de baja
      lógica. Alternativa = `PATCH /api/sensores/{id}` con body `{estado:INACTIVO}`
      (más explícito pero duplica a FEAT-0004). Requiere decisión humana.
- [x] Idempotencia de re-baja: RESUELTO (humano 2026-09-09) = **204 idempotente** (re-baja no-op).
      Alternativa = `409` con code (p. ej. `SENSOR_ALREADY_INACTIVE`) para alertar
      de una re-baja. Requiere decisión humana.
- [x] Visibilidad post-baja: RESUELTO (humano 2026-09-09) = **se mantiene visible** en listado y
      detalle (consistente con FEAT-0002/0003). Alternativa = ocultar INACTIVO de
      los endpoints de lectura (rompería AC-007 de FEAT-0003 y el listado de
      FEAT-0002 — cambio retroactivo). Requiere decisión humana.
