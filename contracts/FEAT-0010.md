## Intent
Crear el microservicio `data-simulator` (services/data-simulator): genera **lecturas
sintéticas** por sensor (curva base + ruido + anomalías) y las publica a RabbitMQ en el
exchange `sensor.lecturas` (topic, key `lectura.{sensorId}`) a la frecuencia de cada
sensor, para alimentar el pipeline (FEAT-0011 `ingestion-service`). Con control de
arranque/parada/anomalía. Fuente spec: §8 (funcional), §6 (contrato de mensajería),
§9.3 (port de entrada abstraído), §9.5 (6 sensores seed Paraná+Salado), stack.md
(reactivo: WebFlux + Reactor RabbitMQ; cero bloqueante; hexagonal).

## Use Case
**Actor:** Desarrollador/operador (herramienta de datos de prueba)
**Goal:** Producir un flujo continuo de lecturas sintéticas plausibles por sensor hacia
`sensor.lecturas`, controlable en runtime

### Main Flow
1. El actor envía `POST /api/simulador/iniciar` (sin body) → el simulador arranca un
   generador por cada sensor configurado.
2. Cada generador emite una `Lectura` periódicamente (intervalo =
   `frecuenciaReporteSegundos` del sensor): valor = nivel base + variación estacional/
   diaria (seno) + ruido gaussiano; publica en `sensor.lecturas` con key
   `lectura.{sensorId}`.
3. El actor puede consultar `GET /api/simulador/estado`, inyectar una anomalía puntual
   (`POST /api/simulador/{sensorId}/anomalia`) y detener (`POST /api/simulador/detener`).

### Alternative Flows
- AF-01: `POST /api/simulador/iniciar` cuando ya está corriendo → `409` code
  `SIMULATOR_ALREADY_RUNNING` (no duplica generadores).
- AF-02: `POST /api/simulador/detener` sin simulación activa → `200`/no-op
  (idempotente; estado `STOPPED`).
- AF-03: `POST /api/simulador/{sensorId}/anomalia` con sensor no configurado →
  `404 SENSOR_NOT_FOUND` (code del registry).
- AF-04: RabbitMQ no disponible al publicar → reintentos configurables
  (`messaging.retry.*`) y fallo NO silencioso: se loguea y el generador del sensor
  afectado se detiene (escalable a DLQ en ingestion; acá solo se notifica).
- AF-05: `anomalia` sin simulación activa → `409 SIMULATOR_NOT_RUNNING` (no hay a
  quién inyectarla).

## Business Rules
- BR-001: Un generador por sensor configurado; intervalo de publicación =
  `frecuenciaReporteSegundos` del sensor (≥ 1 s; valores de demo configurables en
  `application.yml`, nunca hardcodeados).
- BR-002: La `Lectura` publicada tiene contrato formal
  `{"sensorId": UUID, "timestamp": instant, "valor": decimal, "unidadMedida": "METROS|CENTIMETROS"}`
  en exchange `sensor.lecturas` (topic durable), routing key `lectura.{sensorId}`,
  **sin** `severidad` (la calcula ingestion en FEAT-0011).
- BR-003: Valor sintético plausible: nivel base por sensor (≈ altura de alerta de
  referencia §9.5) + componente estacional (seno 24 h) + ruido gaussiano
  (σ configurable). La anomalía puntual desplaza el valor hacia la banda superior
  (`rangoWarning`/`rangoCritical` del sensor) durante `anomalia.segundos` (default
  configurable) y luego vuelve.
- BR-004: Estado de la simulación: `STOPPED` ↔ `RUNNING`, transiciones solo por
  `/iniciar` y `/detener`; iniciar corriendo → `409 SIMULATOR_ALREADY_RUNNING`;
  detener detenido → no-op idempotente. Estado en memoria (sin Redis en v1).
- BR-005: Inyectar anomalía en sensor no configurado → `404 SENSOR_NOT_FOUND`; sin
  simulación corriendo → `409 SIMULATOR_NOT_RUNNING`.
- BR-006: Configuración de los sensores v1 = **config local** (los 6 seed de §9.5:
  `PARANA-RECONQUISTA`, `PARANA-SANTAFE`, `PARANA-ROSARIO`, `SALADO-SANJUSTO`,
  `SALADO-RECREO`, `SALADO-SANTOTOME` — con unidad/frecuencia/nivel base/rangos).
  La integración con `sensor-registry` (GET /api/sensores) queda como port futuro
  (ver Ambiguity Log).
- BR-007: Todo el stack reactivo: publisher vía **Reactor RabbitMQ** (nunca
  `RabbitTemplate`); cero `.block()` en producción; configuración de mensajería
  (`messaging.retry.*`) en `application.yml` (nunca hardcodeada — stack.md §9.3).
- BR-008: Sin persistencia en v1 (stateless; estado y anomalías en memoria). El
  reinicio del servicio vuelve a `STOPPED`.

## Acceptance Criteria
- AC-001: GIVEN sensores configurados (6 seed) y RabbitMQ disponible
  WHEN `POST /api/simulador/iniciar`
  THEN responde `200` con `{estado:RUNNING, sensores:6}` y comienzan a llegar
  mensajes al exchange `sensor.lecturas` con key `lectura.<sensorId>` y payload con
  los 4 campos de BR-002 (verificado en el IT con RabbitMQ real).
- AC-002: GIVEN la simulación corriendo
  WHEN `POST /api/simulador/iniciar` de nuevo
  THEN responde `409 SIMULATOR_ALREADY_RUNNING` (sin duplicar generadores).
- AC-003: GIVEN la simulación corriendo
  WHEN `POST /api/simulador/detener`
  THEN responde `200` con `{estado:STOPPED}` y dejan de publicarse lecturas
  (verificado por ausencia de mensajes en un intervalo).
- AC-004: GIVEN la simulación detenida
  WHEN `POST /api/simulador/detener`
  THEN responde `200` con `{estado:STOPPED}` (idempotente, no-op).
- AC-005: GIVEN la simulación corriendo y un sensor configurado S
  WHEN `POST /api/simulador/{S}/anomalia`
  THEN responde `200` y al menos una lectura posterior de S supera su rango normal
  (valor en banda warning/critical) durante la ventana de anomalía.
- AC-006: GIVEN `POST /api/simulador/{no-configurado}/anomalia`
  WHEN el sistema procesa el request
  THEN responde `404 SENSOR_NOT_FOUND`.
- AC-007: GIVEN la simulación detenida y `POST /api/simulador/{S}/anomalia`
  WHEN el sistema procesa el request
  THEN responde `409 SIMULATOR_NOT_RUNNING`.
- AC-008: GIVEN la simulación corriendo
  WHEN `GET /api/simulador/estado`
  THEN responde `200` con `{estado:RUNNING, sensores:[...], lecturasPublicadas:N}`.
- AC-009: GIVEN valores por defecto demo
  THEN cada generador respeta el intervalo configurado por sensor (≥1 s) y el valor
  emitido queda dentro de `[nivelBase - 3σ, alertaMax]` salvo anomalía (invariante
  verificable en unit de generación).

## Entities Affected
- Lectura (payload de salida, dueño del contrato: data-simulator v1; la persistirá
  ingestion en FEAT-0011): `sensorId`, `timestamp`, `valor`, `unidadMedida`.
- Sensor (datos de configuración locales, espejo de §9.5): `codigo`, `unidadMedida`,
  `frecuenciaReporteSegundos`, `nivelBase`, rangos normal/warning/critical.
- Sin persistencia ni entidad nueva en este servicio.

> Notas de implementación (no spec, no generan AC): estructura hexagonal igual que

> "LecturaGeneratorPort" (genera la secuencia) abstrae el futuro protocolo real
